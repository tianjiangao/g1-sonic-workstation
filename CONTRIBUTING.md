# Contributing

Report the exact WBC/GR00T commit, hardware, expected behavior, reproduction commands and redacted error output. Never include credentials, private hostnames, recordings of people or private training data in an issue.

Keep physical left/right semantics, original raw evidence and formal review gates explicit. Explain whether a test used synthetic data, offline real records, isolated simulation or authorized hardware. Preserve failures and limitations. Avoid blanket environment upgrades and changes to site policy locks. New hardware acceptance belongs to its own documented session.
