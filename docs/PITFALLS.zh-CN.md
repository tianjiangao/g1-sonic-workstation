# 集成中的坑与处理原则

| 现象/误区 | 处理与边界 |
|---|---|
| PICO body timestamp 为0，或旧姿态重复出现 | 记录宿主接收/推进信息并做新鲜度检查；不能把“能读到包”当跟踪有效。相关补丁与 `body_freshness.py`、`xrt_runtime.py` 一起使用。断流后的动作和恢复必须单独验收。 |
| 重复 SDK 读取/跨线程生命周期引发不稳定 | 保留 runtime 生命周期管理、原子快照和停止回收；不要绕过 Reader 检查。 |
| Dex1 的 wire left 与物理 left 不一致 | 原机曾实测左右反转；以逐侧现场确认结果配置映射，不能靠变量名猜。 |
| SONIC 默认是 Dex3 七关节模型 | Dex1 每侧只有真实1D；使用官方 Dex1 适配，禁止补零伪造七维训练动作。 |
| 夹爪松开后回不到全开 | 原实现初始开度上限和重复值滤波均影响目标收敛；桥接层已有处理，官方滤波源码保留。启动全开属于真实动作，不能继承软件测试作为机械验收。 |
| 多 RealSense 抢同一台设备 | 明确传递并核对 device_id；用遮挡法确认角色。 |
| 把双目 UVC 头部当成 D435i | 根据 UVC 枚举和实际图像确认；稳定设备别名优先于 video 编号。 |
| YUYV/MJPEG 或带宽导致超时 | 配置实际支持的分辨率、帧率与像素格式；原双腕默认30Hz双流曾超时，15Hz是现场配置，不是普适硬件保证。 |
| 相机代码导入了旧 checkout | 检查进程 cwd、Python 模块来源和固定版本。安装成功与实际三路流到达要分别验证。 |
| 新旧 SONIC/DDS 控制器同时运行 | 启动前检查冲突；不自动结束未知控制进程。热保护、启动状态和模式交接都应保留。 |
| TtsMaker 回包成功却没有声音 | 正式路径采用本地PCM + AudioClient.PlayStream；检查每包返回值并现场听音。音频SDK与控制环境隔离。 |
| 语音排队阻塞采集或保存失败也播报成功 | 异步有界队列；只在真实开始、落盘保存或错误状态后播报。 |
| 15Hz录制/50Hz动作被当相机曝光率 | 记录抽样、动作网格、消息到达、曝光时刻分别说明；当前没有严格跨传感器时钟同步证明。 |
| 29D last_action 被当64D SONIC token | 正式流程从原始事件恢复真实 token；旧 capture/export 仅为29D诊断导出。 |
| VR3PT 零SMPL被默认清洗掉 | 当前流程关闭零SMPL清洗，保留真实token与全部模态的一致性。 |
| 单独去掉重复相机帧 | 禁止；多模态必须一起裁剪或重采样。JPEG内容去重也不是帧时间去重。 |
| 相邻片段随机分 train/validation | 按完整session及来源内容指纹拒绝泄漏。 |
| 清洗/reader通过就当任务成功 | 人工任务审核独立，工程数据永不自动升级。 |
| 模型能加载就当 real2sim 通过 | 需核对坐标、关节名、单位、惯量和资产来源；被动回放与动力学、接触和策略评估分别验收。 |
| 新33DoF XML直接替换旧43DoF控制循环 | 禁止直接替换；旧循环有Dex3维度假设。被动回放模型 nu=0，不接控制循环。 |
| 安装依赖时顺手更新全部环境 | 保留已有独立环境和固定版本；缺什么就说明什么，不靠静默替换解决。 |

原始改动集中在 `patches/wbc-local-fixes.patch` 和 `wbc/` overlay。补丁排除了现场二进制人体标定文件，不是对原工作目录的全量镜像。参考文档保留了集成历史，不能把其中某次实时网络/设备状态当作今天的状态。
