# Dex1 映射与下一轮启动

当前已确认真机夹爪能响应扳机，但2026-10-27试验中闭合端点触发状态保护并停止。新增的保守限制已通过离线测试，尚待再次真机验收。

## 操作

打开桌面 **SONIC 工作站**，点击 **开始下一轮真机验证（SONIC + Dex1）**。确认现场支撑、独立急停和夹爪附近无人后，程序会检查旧控制器不存在、自动启动服务停止、Dex1 服务唯一、LowCmd 静默、LowState 和 PICO 有效，再启动原版 SONIC。

也可在项目目录运行 `./start_real_teleop.sh`，按终端提示输入 `START`。本轮实现未由代理自动执行这个新启动入口，操作者确认后才会创建真机控制器。

1. 等待 `Init Done`，两侧食指扳机先完全松开。
2. 标定站姿按一次 ABXY，全部松开，等待3秒。
3. 按一次 AX 进入 POSE，松开；先确认左右手臂正常。
4. 轻按左食指扳机：左夹爪闭合；松开回到**本轮启动开度**。右扳机同理。
5. ABXY 停止本轮；或控制台 **停止本次作业**／启动终端 Ctrl+C 请求软件停止。独立急停始终保留。

启动时不会将半开的夹爪自动全开。每侧扳机先释放至少0.25秒，首次超过0.1的主动按压才激活该侧；尚未激活的一侧保持当前位置。当前试验范围为 q=min(0.15, 本轮开度) 到本轮捕获的开度，目标变化速度限制为0.5rad/s（不等于实际电机速度保证），并未声称已完成机械零点/全行程标定。首次勿满按或夹持物体。

## 实际链路

PICO 完整原子追踪包 → 现有已验证 SDK 兼容读取 → 本机回环 `dex1_trigger:5558` → 输入换算与新鲜度检查 → 宇树官方 `Dex1_1_Gripper_Controller.control_thread` → `rt/dex1/left/cmd` / `right/cmd` → Orin 官方 `dex1_1_service` → 串口电机。

身体控制仍为 Orin **原版** `target/release/g1_deploy_onnx_ref`，没有使用已停用的 `g1_deploy_real_trial`，也没有修改 SONIC 的 PLANNER/POSE 状态机。

宇树控制循环输入范围5～7，PICO扳机范围0～1。换算按每侧启动开度执行；官方 Kp=5、Kd=0.05、每步0.18rad限幅与平滑滤波保持原样。通过固定 SHA256 的官方类定义加载，避免引入与 Dex1 无关的 Dex3 手部重定向依赖。官方构造函数本会立即发布并无限等状态，适配层改由受控状态订阅和发布边界供数，**控制循环本身未改写**。

上游来源固定在 `profiles/dex1-upstream-lock.json`：Unitree xr_teleoperate 提交 `817fb00c63cde15e5f24a0f8fa08e1e33ed89d3b`，许可证原文保留在 vendor 中。Orin 串口服务为 `ced3216290bb22dae356213993786beeaa7143ab`，只应用了用户已批准的发现命令零初始化修复。

## 失联与停止边界

- PICO包、SONIC模式、策略反馈、左右夹爪状态都需新鲜；过期250ms即停止发布夹爪命令。
- 数据丢失后锁定退出，不自动恢复；需重新启动本轮。
- 宇树串口服务原样使用1000ms命令超时，随后进入BRAKE。**停止发布不等于250ms内电机断电**，也不代替独立急停。
- 官方 Dex1 状态服务本轮保留运行，停止遥操作不会将它误杀；否则无法依赖该服务的超时BRAKE路径。
- 原 SONIC 曾在正常停止后的 DDS 清理阶段异常退出。新入口记录退出码；尚未宣称该上游清理问题解决。

## 验证与限制

- `evidence/dex1-mapping/tests-final.log`：26项本机测试。
- `isolated-e2e-final/result.json`：仅lo、无真实机器人路由，OFF不发布、启动无跳变、左闭合、左释放/右闭合、断流停止且不自动恢复。是真实DDS交换与官方控制循环，但机器人状态为模拟。
- `readonly-pico-result.json`：真实SDK269包，左右扳机字段有效；未发布网络/电机命令。测试时扳机均为0，未假称实际按压或真实开合通过。
- 实际开合、机械方向、零点和夹持效果：**待现场验收**。
- 头部D435i和Dex1训练数据schema仍未完成；本入口记录PICO、夹爪状态/目标、SONIC诊断日志，不冒充完整LeRobot抓取训练数据集。
- SSH复用连接需有效；失效会明确报认证失败。没有保存密码，也没有安装免密公钥。Dex1状态服务未运行时预检会阻止启动。
