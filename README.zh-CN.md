# G1 SONIC 工作站

**把 G1 + PICO + SONIC + Dex1 的遥操、语音反馈、数采、审核和被动 real2sim 回放连接起来。**

[English](README.md) · [安装与现场配置](docs/SETUP.zh-CN.md) · [完整流程](docs/WORKFLOW.zh-CN.md) · [踩坑指南](docs/PITFALLS.zh-CN.md) · [验证记录](docs/VALIDATION.md)

这是在实际集成中积累的社区工程，基于 NVIDIA SONIC / GR00T-WholeBodyControl 和 Unitree 官方硬件接口。目标是让后来者少走从官方教程到真实数采之间的弯路。不是 NVIDIA 或 Unitree 的官方发行版。

## 这里补齐了什么

- **遥操作与夹爪**：工作站统一入口，PICO 数据新鲜度与启动检查，Dex1 官方控制适配、物理左右映射和断流停发。保留官方控制路径，不替换身体控制算法。
- **三路相机**：UVC 双目头部与双腕 D405 的角色配置、指定设备、USB 格式处理和预览。不能把未经枚举的头部设备直接当作 D435i。
- **语音采集反馈**：本地 CPU 中文男声合成，经 G1 AudioClient.PlayStream 播放；开始、保存、中断与失败按实际状态反馈，异步队列不阻塞录制。
- **数采与审核**：保留原始事件、monotonic 接收时间、完整图像和哈希；批次/段号管理、原始帧回放和质量检查。人工确认与机器结构检查分开。
- **正式数据 pipeline**：真实 64D SONIC token + 左右各 1D Dex1，as-of 对齐，官方 exporter / 清洗，真实 Isaac-GR00T reader，验收收据、SSH 哈希交付及训练门禁。
- **real2sim**：已结束 episode 的真实 29D 身体反馈与左右夹爪反馈进入独立被动 MuJoCo 模型，统一时间轴展示图像与关节；原始数据不变。

## 快速开始

先按[安装说明](docs/SETUP.zh-CN.md)准备固定版本官方环境。`tools/prepare.py` 默认只打印计划，显式 `--apply` 才向新工作目录复制代码并向干净的官方 checkout 应用补丁；不会下载依赖、连接机器人、启控或训练。

之后先跑[离线验证](docs/VALIDATION.md)，再按自己的硬件完成相机角色、网络接口、DDS 与物理左右映射确认。公开配置是示例，不能继承原机器的验收结论。

## 流程与边界

遥操采集 → 人工回放/审核 → token 转换 → 官方清洗 → reader/哈希验收 → SSH 交付 → 后训练 → 离线评估 → 隔离仿真 → 单独授权的真机验收。原始记录同时可以进入被动 3D 回放。

**目前 real2sim 是运动学回放，不代表动力学标定、接触抓取成功或策略验证。** 34D 状态、40×66D 动作窗口和 50Hz 动作记录网格不代表相机 50Hz 曝光，更不代表跨传感器时钟同步。

本仓库发布代码、版本来源、补丁、配置示例与经验文档；不上传原始录制、模型权重、私有服务器配置或运行缓存。部分 Dex1 参考模型资产未明确统一分发许可，因此只提供构建器与来源哈希，不打包资产。

正式 pipeline 保留站点策略门禁。原部署规范和哈希锁未改动，也未伪装成通用配置；使用者需要在自己的新工作目录审核现场契约并建立锁，详见安装说明。
